# 资产应用与运维平台扩展及真实接入设计

设计版本 v0.2 · 2026-10-15

平台覆盖负责范围内的实物资产、技术资源、业务应用、网站、账号授权与外部服务，统一回答五个问题：有什么、归谁负责、当前如何、出了问题怎么处理、每次变更有什么依据。现有采购、领用、盘点和财务主线保留，新增服务目录、应用观测、接入中心、告警事件和受控自动化。

当前交付是本地交互原型和目标架构。真实 Agent、网关、数据库、密钥库、SSH/RDP、PVE API、网络和应用采集尚未部署。页面中的联机、诊断、审批及执行结果都是演示数据。

## 1 统一纳管范围

按“组织 → 站点/网区 → 项目/业务服务 → 环境 → 资源”组织对象。一个对象可以关联多个业务服务，责任关系带有效期。管理范围和操作权限由服务端按组织、站点、项目与资源标签限制。

| 对象 | 应保存的信息 | 与其他对象的关联 |
| --- | --- | --- |
| 实物资产和批次物资 | 采购、价格、供应商、SN、数量、保管人、位置、维保、状态 | 原始单据、交接、盘点、财务期间 |
| 物理机、Windows、Linux | 硬件、OS、补丁、服务、进程、软件、监听端口、活动证据 | 实物资产、账号、网卡、IP、应用实例 |
| PVE、VM、容器和 Kubernetes | 集群、节点、实例、模板、镜像、配额、到期日 | 宿主机、存储、网络、项目、业务服务 |
| 交换机、路由器、防火墙、AP、VPN | 健康、接口、邻居、配置版本、线路、采样流量 | VLAN/VRF、端口、线缆、地址、站点 |
| IP、DNS、DHCP、域名、证书 | 分配记录、发现证据、有效期、解析、证书链、续期 | 网卡、应用入口、负载均衡、责任人 |
| 应用、API、网站和内部服务 | 负责人、环境、等级、入口、版本、部署实例、应急手册 | 数据库、缓存、队列、主机、证书、发布 |
| 数据库、Redis、MQ、存储、备份 | 实例、容量、性能、复制、任务、备份、恢复演练 | 应用依赖、数据责任、恢复目标 |
| 云资源、SaaS、软件许可证 | 账号、订阅、用量、到期、预算、授权分配 | 部门、项目、成本中心、供应商 |
| 机房、机柜、UPS和环境设备 | 位置、U位、电力、温湿度、维保、告警 | 设备与供电链路；协议支持后纳管 |

每类接入都有能力边界。设备不支持流量导出就不能承诺每个 IP 的详细流量；应用未埋点时只能提供外部拨测和已有服务指标。自有系统通过 API、Agent、Exporter 或 SDK 接入；第三方 SaaS 以官方接口、授权回调或人工台账管理。

平台可将常用应用放入服务门户，按资源权限提供“打开应用”和 SSO 入口。内嵌网页只用于应用自身允许嵌入的场景，遵守 CSP、Cookie 与来源隔离；不绕过登录或在页面保存外部系统密码。管理入口、监控接入和操作权限是三个独立能力。

## 2 真实环境部署架构

### 2.1 中央平台

建议起步采用模块化后端和独立任务进程，保留模块接口，规模需要时拆分。

| 层 | 职责 | 起步实现建议 |
| --- | --- | --- |
| Web 和业务 API | 业务流程、服务目录、查询、授权、审批、导出 | Python/FastAPI 或团队熟悉的后端，OpenAPI 接口；不是让浏览器直接连设备 |
| 业务账本与关系模型 | 资产、单据行、服务、资源关系、权限、任务权威状态 | PostgreSQL；事务、唯一约束、版本控制、Outbox |
| 调度与执行 | 采集计划、外部 API 任务、重试、回读与补偿 | 独立 Worker；队列用于派发，PostgreSQL 保留可恢复任务记录 |
| 凭据与身份 | SSO、MFA、凭据引用、短期授权、轮换 | 对接现有身份源和密钥库；敏感字段不返回前端 |
| 观测数据 | 指标、日志、trace、流量、查询与保留 | OTel 接入；按需要整合 Prometheus/兼容时序库、Loki/日志库、Tempo/追踪库等 |
| 附件与审计 | 验收、合同、签收、会话记录、独立日志 | 对象存储与独立审计存储，按权限与保留规则访问 |

这些是候选技术，不是已安装组件。已有 Zabbix、Prometheus、日志平台、堡垒机或备份平台可通过连接器整合，先统一身份、资源关联和工作流，避免重复采集和重复存储全部原始数据。

### 2.2 站点采集与执行网关

总部机房、办公网、分支机构、隔离业务网按实际可达范围部署网关。网关部署于允许管理目标的网区，默认向中央平台主动建立经过验证的 mTLS 通道，通常使用出站 443；采集和任务通过该受控通道交互。网区间无需开放任意互通。

网关提供协议适配、限流、本地加密缓冲、源时间保留、任务回执和健康上报。网络恢复后按事件 ID 去重补传；缓冲满时按数据类别执行明确的丢弃/背压策略，不能静默丢弃业务账本或操作结果。高价值站点可部署冗余网关，并通过租约控制单个采集任务的执行权。

Agent 和网关首次注册使用限时、一次性注册令牌换取设备证书，绑定站点与身份。证书支持轮换和吊销，安装包及升级包签名校验、灰度发布。克隆虚拟机必须重新生成 Agent 身份，防止多个实例冒用同一证书。

### 2.3 协议与采集能力

| 目标 | 采集方式 | 可以得到什么 | 控制能力及条件 |
| --- | --- | --- | --- |
| Windows | 首选只读 Agent，必要时 WinRM over TLS/CIM | 软硬件、事件、服务、补丁、进程、监听、心跳 | 独立授权后执行脚本、服务维护、文件任务；RDP 会话走专用网关 |
| Linux | Agent/Exporter，必要时 SSH 只读命令 | 软硬件、系统服务、进程、指标、日志、端口 | SSH 密钥/短期证书；限制命令和 sudo 范围 |
| PVE | HTTPS API、任务查询、必要的来宾 Agent | 节点、VM、存储、任务、资源归属 | API Token 限资源池权限；创建和回收使用异步任务 |
| 网络设备 | SNMPv3、设备 API、LLDP、Syslog | 状态、接口计数、邻居、设备事件 | SSH/NETCONF/RESTCONF 等按厂商能力适配；变更前备份并回读 |
| 单 IP 流量 | NetFlow/sFlow/IPFIX 或授权流量传感器 | 源/目的、协议、端口、会话量、采样流量 | 标记采样率、方向、观测点，避免重复汇总 |
| IP/DNS/DHCP | DHCP 租约、ARP/邻居、DNS API、受控发现 | 分配、占用证据、冲突、解析和历史 | 分配事务、短期预留、DHCP/网络策略下发后回读 |
| Web/API | HTTP/TLS/DNS 拨测、浏览器合成测试 | 访问阶段耗时、状态、内容、证书、业务流程 | 从指定探测网区访问，经授权的测试账号保存在密钥库 |
| 应用内部 | OpenTelemetry SDK/自动埋点、Exporter、日志管道 | 请求、错误、延迟、调用链、日志及实例性能 | 需兼容应用语言和框架；未埋点不能臆造 trace |
| 数据库及中间件 | 专用只读监控账号、Exporter/管理 API | 连接、锁、慢查询摘要、复制延迟、队列积压 | 变更权限独立授予，不默认让监控账号执行管理命令 |

建议周期：心跳和关键服务指标 30–60 秒，普通设备 60–300 秒，软件全量清单 6–24 小时加变更增量。最终周期依据规模、网络和设备负载测试确定。任何指标均显示来源、源采集时间、接收时间和过期阈值。

## 3 资源身份与可信关联

定义稳定的 resource_id、asset_id、service_id 和 instance_id。IP 是可变属性，不是永久主键。匹配使用来源系统 ID、硬件 UUID/SN、Agent 证书、PVE cluster+VMID 等组合；MAC 只作为辅助证据。跨站点重叠地址以站点/VRF和子网区分。

发现流程为：只读发现 → 候选池 → 身份匹配 → 差异复核 → 人工或规则认领 → 绑定管理策略。重复对象合并保留来源和引用映射；删除来源对象不删除历史业务记录。

字段权威来源分开：采购价格来自确认采购，保管人来自交接，IP 分配来自 IPAM，系统版本来自主机采集，VM 状态来自 PVE。自动观测不能覆盖已确认价格、责任人或业务生命周期；冲突进入复核队列。

资源关系示例：业务服务 → 域名/证书 → 入口负载均衡 → 应用版本 → 应用实例 → VM/容器 → PVE节点/物理机 → 网卡/IP → 交换机端口，同时关联数据库、缓存、队列、存储、备份、负责人和成本。每条关系带来源、发现时间和有效期，未知关系保持未知。

## 4 应用与网站监控

### 4.1 服务目录

每个业务服务保存：名称、负责人、维护组、业务等级、生产/测试环境、访问入口、承载资源、依赖、发布版本、值班组、监控策略、应急手册、成本归属、备份要求和生命周期。应用软件的“已安装”与业务服务的“运行健康”分开。

### 4.2 四层观测

1. **入口层**：DNS 解析、TCP 连接、TLS 证书链与有效期、HTTP 状态、重定向、内容断言、阶段耗时和指定位置的可用率。区分内网和外网探测，单个探测点不能代表全部用户可达。
2. **用户操作层**：浏览器合成测试验证登录、检索、提交等关键路径；测试使用专用账号和可清理数据，避免支付、发信或生产数据变更。RUM 按需采集页面性能、JS 错误和体验分布，先明确同意、脱敏与保留范围。
3. **应用层**：吞吐、错误率、p50/p95/p99 延迟、线程/连接池、运行时、实例负载、错误日志与调用 trace。日志通过 trace_id 关联请求，按 service_id、环境、版本、实例归集。
4. **依赖层**：数据库慢查询摘要/连接/锁、Redis 内存/命中、MQ 积压、存储延迟、上游 API 失败和实例资源饱和。结合依赖关系解释受影响服务，关联性不直接认定根因。

可用率、SLO和响应分位数标明观测窗口、覆盖率、维护窗口和排除条件。多实例 p95 不能简单平均；以兼容的原始分布或直方图聚合。没有有效探测时显示未知。

### 4.3 网站安全与接入控制

HTTP/浏览器探测在受限网关执行，按站点授权目标、协议、端口和网络范围。每次解析及跳转都检查目标范围，防 DNS 重绑定和跨范围重定向；禁止默认访问云元数据端点。内部应用使用显式授权范围，不能仅做“只允许公网”而使内网监控不可用。

凭据以引用方式注入指定探测任务，不存入 URL、脚本参数日志或导出。日志、trace、截图和请求头按字段脱敏；记录认证或业务结果所需的最小证据。

## 5 远程访问与自动化

### 5.1 两种远程路径

- 浏览器 SSH/RDP：浏览器 → 会话网关 → 目标。网关执行资源授权、凭据获取、连接与会话审计；按范围控制文件传输、剪贴板和磁盘重定向。
- 本地 mstsc：提供无密码的连接配置，并验证用户网络路径。直接从电脑连目标的 RDP 会话不能仅靠平台入口获得完整录屏/命令审计；需要通过受控 RD Gateway/堡垒机及终端策略才能落实对应审计范围。

Windows 多用户独立桌面按受支持的 Windows Server/RDS 版本、部署和有效授权实现。管理会话与员工业务桌面是不同用途，不能通过修改客户端限制实现。

文件任务区分“上传到平台暂存”与“已传到目标”。校验权限、目录白名单、大小、哈希、文件检测及目标回执；下载和失败也留痕。

### 5.2 任务状态与一致性

流程：申请 → 参数预检 → 独立审批 → 待执行 → 执行中 → 外部结果回读 → 健康验证 → 完成。旁路状态包括驳回、过期、失败、待补偿和人工接管。审批绑定参数版本、目标集合、有效期与批准者，不能在执行前偷偷换目标。

任务保存 request_id、资源锁/租约、参数版本、操作者、批准者、执行器身份、凭据引用、外部任务 ID、每步前后状态、回执和恢复计划。队列按至少一次投递设计，执行器以幂等键和外部状态防重；非幂等命令超时后先核实结果，不宣称所有远程动作可以严格 exactly-once。

PVE 创建链：预检模板/配额 → 短期预留 IP → 分配 VMID → 提交创建 → 跟踪 UPID → 初始化 → 网络验证 → Agent 注册 → 关联服务/资源台账。创建 VM、来宾初始化、业务健康是不同成功阶段。补偿仅回收本请求实际创建且确认未被接管的对象；不盲删磁盘或释放已在用地址。Windows 镜像的初始化需要相应模板和来宾初始化组件，不能照搬 Linux Cloud-Init。

## 6 告警工单与变更处理

统一接收指标、日志规则、拨测、设备事件、备份失败与到期提醒。告警具有规则、对象、环境、严重度、触发/恢复时间、原始证据、责任组和关联事件。

处理链：发现 → 去重/聚合 → 确认 → 分派 → 诊断 → 变更申请/预案 → 处理 → 回读与恢复验证 → 复盘/知识库。确认不等于恢复，关闭事件不能伪造监控恢复。维护窗口、依赖抑制、值班路由和超时升级减少告警泛滥，但保留原始记录。

例：官网请求变慢 → 关联入口和应用 → trace 显示数据库等待 → 定位相关实例/发布 → 创建工单 → 审批后处理 → 同时核验业务路径和性能 → 保存全过程。平台展示证据和影响，不在证据不足时自动认定根因或批量重启。

## 8 平台可靠性与容量

业务账本、密钥、对象附件和审计都制定备份与恢复方案；平台不可用时保留经过审批的紧急访问路径，并补录审计。外部独立探针监测平台，避免只由平台监测自己。升级包含数据库迁移验证、连接器兼容版本和回退流程。

容量按事实估算：设备数 × 每设备指标序列数 × 采样频率 × 保留时长，另计日志日增量、trace 采样、流量采样和文件审计。开发前收集这些参数，不从原型中的 248 件样例推断生产规模。优先控制高基数标签；用户 ID、完整 URL 和请求 ID 不作为默认指标标签。

数据按业务、短期原始观测和长期聚合设置保留期限。任务/业务流水与采样指标使用不同可靠性策略。日志与trace不能默认无限保存。

## 9 逐步接入与验收

1. **打通最小真实链路**：一个站点网关、少量 Windows/Linux、一个 PVE 资源池、一台交换机、一个内部应用和一个 Web 入口；先只读，确认字段、身份和采集健康。
2. **关联业务责任**：认领资源、关联实物与服务、确定负责人、环境和成本，核对IP/网卡/VM关系；将原型数据迁出正式环境。
3. **完成观测处理链**：启用阈值、维护窗口、通知和工单，模拟服务故障及探针失联，验证两类状态能区分。
4. **按资源开放控制**：SSH/RDP与文件传输先单独验收，再启用 PVE 创建和有限的运维模板；测试审批过期、重复投递、超时后回读与中途失败。
5. **扩大覆盖**：按实际环境接入数据库、容器、云、SaaS、备份、成本与安全能力，每类有能力矩阵和验收用例。

正式验收至少覆盖：设备重装/克隆的身份冲突、Agent吊销、网关断网补传、主机离线与应用未知、HTTP重定向越界拦截、跨角色越权、PVE创建超时、IP并发预留、文件回执、远程审计边界、工单恢复验证、告警去重与平台恢复演练。

实施配置仍需收集：设备和应用数量、站点/网段、已有监控及身份系统、是否允许Agent、设备协议版本、Windows授权、PVE版本/模板、隔离网络要求和保留/恢复目标。它们用于确定部署容量和连接器配置，不影响先确认整体产品范围。
