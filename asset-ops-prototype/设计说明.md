# 栖云 · 资产与运维

产品设计草案 · 2026-10-08

把“这台设备怎么买来的、现在归谁、放在哪里、运行如何、花了多少钱”放进同一张资产卡，并允许从任意汇总数字追溯到原始单据、实际交接和采集证据。

本文依据用户提供的流程图和本次需求设计。既有《物品资产管理—财务对账字段与规则》用于理解采购、领用和财务关联，不视为用户另行下达的指令。下文明确区分本次提出的能力、建议补充的能力与尚需业务确定的实施口径。

## 1. 雏形的定位

这是可用于讨论导航、信息层级和业务操作的浏览器演示原型。资产、人员、单据、流量和告警均为示例数据；远程连接、采购审批、PVE 创建、扫描和网络设备操作不连接真实环境，也不代表真实执行成功。实际能力应在接入与权限配置完成后逐项验收。

原型把系统分为三个相互关联的视角：

- **业务资产**：采购、验收、领用、出入库、归还、调拨、维修、盘点及财务对账。
- **技术资源**：Windows／Linux 主机、虚拟机、软件、端口、IP、网卡、网络设备与运行观测。
- **责任与证据**：使用人、保管人、部门、位置、审批、交接、操作审计及凭据授权。

单台资产详情是三个视角的交汇点；首页用于发现需要办理或处理的事项，台账用于筛选与追溯。

## 3. 页面结构

建议主导航为：总览、资产台账、采购与流转、主机与远程、PVE 虚拟化、IP 地址管理、网络与流量、盘点与财务、审计与设置。

**总览**优先显示总资产、在用／在库、在线观测、待处理事项和资产原值，配合使用趋势与流转队列。数值应带口径，例如“纳入监控的主机在线率”，避免把耗材或没有采集器的设备算成离线。

**资产台账**提供编码／序列号／名称／IP／人员搜索，以及类型、部门、生命周期、在线状态、位置筛选。详情呈现概览、配置、网络、软件、采购与成本、责任与流转、审计。主要动作按角色及资产状态显示。

**资产详情示例**：某台 Windows 笔记本的卡片同时展示“在用、分配给陈某、研发部、最后心跳 8 分钟前、最后交互活动 2 天前、取得 2 年 3 个月”。心跳与活动数据缺失时显示“未知／未采集”。

**工作队列**按“待审批、待验收、待交付、待签收、待处理差异”组织，避免将审批通过与业务实际完成合并成一个按钮。

## 4. 四种状态必须分开

| 维度 | 示例 | 判断依据 |
| --- | --- | --- |
| 资产生命周期 | 待到货、在库、在用、维修、封存、待报废、已处置 | 经审批及确认的业务事件 |
| 责任与位置 | 使用人、保管人、部门、成本中心、仓库／库位／机柜 | 实际交接、调拨及盘点 |
| 在线观测 | 在线、离线、采集异常、未知、维护中 | 心跳、API、SNMP 或探测结果与超时阈值 |
| 使用活跃度 | 最近活动时间、连续无活动天数、待回收建议 | 经授权采集的登录／会话／业务活动证据 |

**离线时长不等于未使用时长。** 笔记本可能断网使用，服务器可能没有交互登录但持续提供服务，采集器故障也会造成心跳缺失。界面分别标注“最后成功观测”“离线持续时间”“最近活动证据”，并保留来源。不能仅凭离线自动收回、关机或报废。

“购买多少年”以取得日期计算，并区分采购日期、验收入库日期、启用日期；财务折旧起算日期是独立字段。

## 5. 数据模型与追溯规则

### 5.1 实体与关联

- **物品型号**保存分类与规格；耗材按物品、批次、仓库和数量管理。
- **实体资产**一物一码，关联序列号、采购来源、责任、位置、成本和生命周期；编码不因换人或调拨而变化。
- **技术资源**代表操作系统实例、物理主机、PVE 节点、VM 或网络设备。VM 是逻辑资源，关联宿主节点和业务归属，不与服务器硬件混为一件实物资产。
- **网卡与网络地址**独立建模：一台资源可有多张网卡，每张网卡可有多个 IPv4／IPv6 地址；地址带所属子网、VRF／租户及有效时间。迁移与地址变更保留历史。
- **人员、部门、成本中心、位置、供应商**使用稳定 ID；业务发生时保留必要名称快照，避免改名破坏历史报表。
- **单据与明细行、审批版本、业务流水、观测记录、远程会话**分别记录，不能用一张不断覆盖的资产表代替全部历史。

追溯路径：采购申请／审批实例 → 实际采购行 → 验收入库行 → 批次或资产编码 → 领用审批与出库行 → 实际交接 → 流转流水 → 盘点／更正 → 财务期间及报表明细。

### 5.2 业务一致性

1. 审批通过只进入待办理；实际收发或交接确认后，才在一次事务中更新单据、台账和流水。
2. 一次采购可分批入库，一次领用可部分交付。关联到明细行，并记录本次确认数量，不能仅关联整张单据。
3. 每次确认使用唯一幂等标识；重复提交或接口重试不能重复入账。并发领用应防止负库存或同一资产分配给两人。
4. 审批保存单据版本；关键字段变化后按规则重新审批。
5. 已确认记录保留原貌。错误通过关联原单的冲销、更正或调整处理，完整保留操作者、原因、时间和前后值。
6. 业务发生日期、确认时间、财务期间分别保存。关账后的补录与调整按明确的财务政策处理。
7. 暂估、待定价与正式成本分开；未知金额不显示成 0。金额按币种、税务与成本口径统计。

### 5.3 财务边界

资产领用改变状态与责任，不自动等于当期费用或资产灭失。采购原值、库存成本、折旧与账面净值是不同口径。

财务对原始采购、收发与交接数据只读，可标记核对结果并发起差异处理，由授权业务角色更正。首期以数量、单据与成本核对为主；固定资产认定、折旧方法／年限／残值、发票匹配、付款及凭证接口属于后续明确的会计功能，不能把“对账通过”显示为“已记账／已付款”。

盘点使用基准快照与明确的截止时间；盘点期间继续流转的资产必须通过期间流水解释差异。发现差异不直接改账，核准后生成调整记录。

## 6. 主机、远程与网络能力的边界

### 6.1 主机采集与远程

Windows／Linux 主机通过受控采集器或已有管理接口提供硬件、操作系统、软件、补丁、服务和监听端口。每项数据保留采集时间及来源；采集失败与设备离线分开标记。

- **SSH**通过授权密钥或短时凭据连接；记录操作者、目标、授权依据和会话结果。浏览器终端需要后端会话网关。
- **Windows 本地 mstsc**可生成连接参数与 `.rdp` 文件；浏览器不能假定本机一定能直连目标，也不应把密码写入下载文件。原型只说明连接入口与配置。
- **Windows 多用户**必须依据目标 Windows 版本、会话配置和有效授权设计。管理用途的远程会话与 RDS 多用户业务桌面分开；需要多用户桌面时核验相应 Windows Server／RDS 授权与 CAL。不能通过修改系统或绕过会话限制实现并发。
- **上传下载**按主机能力选择 SFTP、受控文件网关或经过策略允许的 RDP 重定向；实现路径权限、大小限制、传输审计与必要的文件检测。页面上传到系统不等于已经上传到目标主机。
- **监听端口不等于外部可访问**。本地监听、主机防火墙规则、网络 ACL 和从指定网络视角探测到的可达性分别展示。

远程、文件传输、重启和高权限命令应独立授权，凭据存入服务端密钥库，避免前端、日志与导出泄漏。

### 6.2 IP 地址管理

IP 状态建议为：可分配、已分配、保留、观测到占用、冲突、未知。地址池还包含网关、网络地址及广播等不可分配用途。

“可分配”来自权威分配记录、保留策略与观测校验的共同判断。**Ping 不通不能证明 IP 空闲**；设备可能禁 ICMP、休眠、跨网段不可达或暂时离线。应结合 DHCP 租约、DNS、ARP／邻居表、网卡清单、交换机 FDB 与管理记录，注明证据时间。

MAC—IP 对应关系支持历史记录和冲突提示。“登记绑定”不代表已在网络中强制生效；DHCP 保留、交换机安全策略或网关绑定需分别接入并回读核验。MAC 也不应作为永久唯一身份，需考虑随机 MAC、网卡更换和虚拟机迁移。

设计需纳入 IPv6、子网／VLAN／VRF、DHCP 范围、DNS 记录、地址保留和跨站点重叠地址。首次接入优先读取已有管理信息；主动端口探测由管理员指定授权范围、频率与时间窗，不能默认扫描全部网络。

### 6.3 网络设备与流量

交换机／路由器通过 SNMP、设备 API 或受控 CLI 提供设备健康、接口收发速率、利用率、错误／丢弃、链路邻居及状态；须能识别计数器重置和采集间隔。

SNMP 接口计数只能说明接口总体流量，不能独立提供每个 IP 的详细流量。按源／目的 IP、端口、协议统计的流量需要设备支持并启用 NetFlow／sFlow／IPFIX 等来源，或其他授权流量传感器；采样与覆盖范围影响精度。界面标明采样、时间窗、来源接口及未覆盖部分，避免把双向或多个观测点的同一流量重复相加。

## 7. PVE 与 Cloud-Init

资源页显示集群、节点、存储、网络、模板、VM、容量与任务；业务页能回答 VM 为谁创建、归属哪个项目、占用哪些资源、何时到期。

创建流程建议：选择经验证的 Cloud-Init 模板 → 指定项目／负责人／有效期 → 选择节点、存储与资源配额 → 选择网桥／VLAN／子网 → 预留地址 → 指定主机名、用户和 SSH 公钥 → 容量与配置预检 → 授权确认 → 提交异步任务 → 跟踪任务 → 初始化与连通性核验 → 登记资源、地址和审计结果。

实现时需处理：

- 模板预装所需初始化组件；初始原型默认以 Linux Cloud-Init 模板为例，不能假定 Windows 镜像使用完全相同流程。
- API 令牌保存在后端并按集群／资源池限制权限；不出现在浏览器源码中。
- 为请求生成唯一标识，保存 PVE 返回的任务标识和资源 ID；超时后先查询实际结果，防止盲目重试创建重复 VM。
- IP 预留、VM 创建、初始化和登记是跨系统步骤，应能补偿与人工恢复；失败时清楚展示已创建资源和待释放地址，不能仅显示一个笼统失败提示。
- VM 创建成功、系统初始化成功、网络可达、采集器上线是不同状态。
- 删除 VM、删除磁盘、修改网络或批量操作使用对应权限与确认；备份、恢复验证和回收策略是独立任务。快照不等于备份。

## 8. 建议补充的能力

以下是设计建议，不代表用户已确定全部纳入首期。

| 优先级 | 建议补充 | 解决的问题 |
| --- | --- | --- |
| 高 | 离职／转岗交接、借用到期、归还与调拨 | 设备与权限随人员变化及时回收，责任不丢失 |
| 高 | 维修、保修／维保到期、备机、报废及数据擦除证明 | 资产从采购一直闭环到安全处置 |
| 高 | 角色权限、组织范围、SSO／MFA、凭据库、操作与远程审计 | 业务、财务、IT 与外包人员有不同权限边界 |
| 高 | 采集健康、最后观测、告警确认／静默／维护窗口 | 区分设备故障与监控失效，减少重复告警 |
| 高 | 数据库及配置备份、恢复演练、灾难恢复目标 | 系统及运维平台本身也需要可恢复 |
| 中 | 软件许可证、版本与补丁生命周期、授权分配 | 软件安装清单能够进一步用于合规与升级治理 |
| 中 | 发票、合同、维保费用及成本中心 | 逐步形成设备全生命周期成本与财务系统关联 |
| 中 | 自动发现后的待认领池、重复资产合并审核 | 避免把发现的每个 IP 都当成新资产 |
| 中 | 机柜／端口／线缆／上联关系、设备配置备份 | 故障时可定位到链路及变更，而不仅是 IP |
| 中 | 项目配额、VM 到期、容量预测、资源回收建议 | 防止虚拟资源长期闲置和资源池超售失控 |
| 中 | 工单、变更审批、维护记录与告警关联 | 技术变更与业务影响能够追溯 |
| 中 | 数据保留期限与员工隐私规则 | 仅采集管理所必需的活动元数据，限制查看范围 |

## 9. 实施架构与阶段

采用统一业务入口与权限体系，业务账本和监控观测分别存储：关系数据库承载资产、单据与权限；时序存储承载持续指标；附件存储承载合同、验收和签收证据。后台任务负责采集、审批同步与 PVE 操作，使用连接器访问各环境。远程会话网关与凭据库单独限制访问。

业务成功以数据库事务与流水为准；外部平台操作以异步任务和实际回读为准。连接器异常不应阻止查看已有台账，并应明确数据是否过期。初期可先使用结构清晰的单体服务加任务进程，不必为雏形引入大量微服务。

### 阶段一：资产业务 MVP

交付主数据、采购／验收、领用／实际交付、归还／调拨、唯一编码、角色权限、追溯、季度／年终盘点与财务核对导出。先选一个部门或仓库验证真实流程。明确含税／成本、计价、会计期间及审批口径后再投入正式账务使用。

验收重点：分批收货、部分出库、同一资产并发领用、重复确认、驳回不出库、调整留痕，以及报表与来源明细一致。

### 阶段二：主机与网络运维

接入受控的 Windows／Linux 采集、IPAM、网络设备观测、告警和远程访问。先完成发现—匹配—认领—授权流程，再扩大采集范围。按实际设备能力接入流量来源。

验收重点：采集过期提示、多网卡多 IP、IP 冲突、离线与活动证据区分、跨角色数据隔离、凭据不外泄，以及远程与文件操作审计。

### 阶段三：PVE 自动化

先交付只读集群资源与任务视图，再启用模板化创建、IP 预留、配额、有效期、回收、备份恢复与异常补偿。高影响动作按既定权限上线。

验收重点：超时后不重复创建、任务状态可追踪、失败资源可清理、地址一致、资源归属完整、创建后可验证、恢复演练有证据。

## 10. 雏形评审与正式验收清单

### 当前雏形适合评审

- 是否能快速找到“归谁、在哪、多少钱、当前什么状态”。
- 资产详情的信息顺序与字段是否符合日常工作。
- 采购／领用／盘点／财务的入口及状态名称是否易懂。
- 主机、VM、IP 与网络设备能否以资产为核心关联理解。
- 危险操作、只读观察和模拟行为是否有明确提示。

### 正式系统必须验证

- 每件实体资产有稳定身份；耗材按批次和数量管理；VM 与实体硬件区分。
- 每个统计结果可下钻到同口径的明细；数量、单位、币种和期间不混算。
- 审批、实际业务确认、采集观测和远程操作不会相互冒充状态。
- 原始单据与已确认流水不能被静默覆盖；更正、回调重试及并发操作可验证。
- 盘点差异经过核准；财务不能直接改写采购／行政原始数据。
- IP 可分配判断有权威记录与观测证据；未响应、未知与空闲分别呈现。
- PVE 任务、远程连接及文件传输有真实结果回读，失败显示准确原因与恢复路径。
- 数据访问、导出、远程、凭据及高风险操作通过权限和审计测试。
- 备份有实际恢复验证；版本升级与连接器故障有回退及恢复方案。

## 11. 当前假设与尚待明确的实施口径

为便于先看雏形，暂按一个组织、多个部门／仓库／机房、人民币示例金额、Windows／Linux 混合主机和一个 PVE 环境设计。示例业务日期为 2026-10-08；不据此推断真实资产规模或环境配置。
